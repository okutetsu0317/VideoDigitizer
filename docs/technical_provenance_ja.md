# 技術実装の来歴

この文書は、VideoDigitizerの主要計算が一般的な数式と公開APIに基づく独立実装であることを記録するものです。特定の市販製品の内部仕様、画面、出力形式を実装仕様として使用していません。

## フレーム取得

- 動画のメタデータ取得とフレーム復号にはOpenCVの公開 `VideoCapture` APIを使用します。
- macOS配布版のOpenCVはソースからビルドし、FFmpegを無効、Apple AVFoundationを有効にします。
- ビルド対象はmacOS 15以降に固定し、ビルド機のOSバージョンが最低動作環境へ混入しないようにします。
- AVFoundationではフレーム番号指定が動画によってずれるため、CFR動画は `frame / fps` から求めた時刻でシークします。実動画の先頭・中央・末尾について、逐次デコード結果と一致することをリリース前に確認します。
- ブラウザへ渡すフレーム画像はOpenCVの公開 `imencode` APIでJPEGまたはPNGへ変換します。
- 出力座標は縮小表示ではなく、元動画の幅と高さを基準に保存します。

## 4点平面較正

画像上の4点 `(x, y)` と対応する平面実座標 `(u, v)` から、射影変換行列 `H` の未知数8個を求めます。`h33 = 1` とし、4組から得られる8本の一次方程式を部分ピボット付きガウス・ジョルダン法で解きます。

```text
u = (h11*x + h12*y + h13) / (h31*x + h32*y + 1)
v = (h21*x + h22*y + h23) / (h31*x + h32*y + 1)
```

実装は `web_viewer/app.js` の `solveLinearSystem`、`calibrationTransform`、`transformPoint` にあります。固有形式の読み書きは行わず、較正点はJSON、CSV、TSVまたはテキストから一般的な数値データとして読み込みます。

## レンズ補正

任意機能のレンズ補正は、焦点距離、主点、半径方向係数 `k1`、`k2`、接線方向係数 `p1`、`p2` を使う一般的な放射・接線歪みモデルです。逆変換は6回の反復計算で近似します。

## 点の予測と補間

- 前フレーム予測は、同一マーカーの直近最大10点に対してフレーム番号を説明変数とする単回帰をX座標とY座標へ個別に適用します。
- 予測点は手入力点と区別して保存し、信頼度、使用点数、移動量上限超過を記録します。
- 欠測補間は線形補間、直前値保持、最近傍の3方式です。処理対象は設定したフレーム範囲内に限定します。

## 基本分析

- 距離は2点間のユークリッド距離です。
- 角度は2ベクトルの内積から `acos` で求めます。
- 速度は座標差をフレーム時刻差で除して求めます。
- 加速度は前後区間の速度差を時刻差で除して求めます。
- 移動距離は隣接する有効点間の距離の総和です。

これらは研究上一般的な計算であり、派生点、欠測、平滑化、較正の有無が結果へ影響します。解析前に動画と座標を照合し、用途に適した方法かを利用者が確認する必要があります。

## データ形式

- プロジェクト: VideoDigitizer独自のJSONデータ（拡張子 `.vdproj`）
- 座標表: CSVまたはTSV
- 較正点: JSON、CSV、TSVまたはテキスト
- 独自仕様が非公開の第三者形式について、互換入出力を提供しません。

## 配布ライブラリ

配布時は `scripts/audit_binary_licenses.sh` を実行し、FFmpeg、x264、x265がアプリへ混入していないことを機械的に検査します。第三者ソフトウェアのライセンス原文は配布物に同梱します。

動画デコードはmacOSのAVFoundationが対応するコンテナとコーデックに依存します。配布版の主対象はMP4、MOV、M4Vです。可変フレームレート動画では、フレーム別時刻CSVを併用して時間軸を明示してください。
